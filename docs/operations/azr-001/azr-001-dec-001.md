# AZR-001-DEC-001 — PostgreSQL public-network exception for DEV-SYNTHETIC

**Parent contract:** AZR-001 v0.8  
**Parent section:** §7 — AZR-001-DEC-001 — PostgreSQL public-network exception  
**Status:** APPROVED  
**Approved by:** Project Owner  
**Approved on:** 2026-09-14  
**Scope:** DEV_SYNTHETIC_ONLY

## Decision context recovered from the conversation

DEC-001 did not require further architecture discovery or redesign. The only pending Owner decision was whether to accept or reject the PostgreSQL network exception for DEV-SYNTHETIC.

The decision presented to the Owner was:

- PostgreSQL Flexible Server remains on **Public Access**.
- The Azure Services firewall rule is enabled using:
  - `start_address = 0.0.0.0`
  - `end_address = 0.0.0.0`
- Azure semantics allow connections from Azure services, including resources outside the project's tenant.
- TLS, long/random credentials, least-privilege PostgreSQL roles and RLS remain mandatory.
- The exception applies only to **DEV-SYNTHETIC with synthetic data**.
- It is classified as:
  - `DEV_SYNTHETIC_EXCEPTION`
  - `NOT_PRODUCTION_PATTERN`
- It creates no staging or production precedent.
- Rejection would block AZR-001 until another network topology were explicitly designed and approved.
- VNet, Private Endpoint, NAT Gateway or another network topology must not be substituted silently.

## Owner approval — verbatim

> **Apruebo AZR-001-DEC-001 para DEV-SYNTHETIC: PostgreSQL Public Access con la regla Azure Services `0.0.0.0/0` según la semántica de Azure, aceptando que puede ser alcanzable desde recursos Azure de otros tenants. La aprobación aplica únicamente a datos sintéticos y queda clasificada como `DEV_SYNTHETIC_EXCEPTION` y `NOT_PRODUCTION_PATTERN`. No autoriza ni constituye precedente para staging o producción.**
